# narrator

Техническое задание и исходники конвейера озвучки: текст (рассказ/FB2) → ролевой сценарий → русская аудиокнига MP3.

## Стек

- **TTS: Yandex SpeechKit v1 REST** — единственный приемлемый русский голос.
  - Endpoint: `POST https://tts.api.cloud.yandex.net/speech/v1/tts:synthesize`
  - Auth: `Authorization: Api-Key $KEY`, ключ в vault (`assistant credentials reveal --service yandex --field api_key`, скрипт достаёт сам)
  - Поля формы: `text`, `lang=ru-RU`, `voice`, `emotion`, `speed`, `format=mp3`
  - Лимит текста: ~5000 символов на запрос → реплики склеиваются в чанки <4000
  - Сеть только через `network_mode: proxied`
- **Fallback: edge-tts** (ru-RU-DmitryNeural / SvetlanaNeural) — акцент норм, но ломает вопросительную интонацию.
- **ЗАПРЕЩЕНО: Deepgram Aura-2** — русский с неисправимым акцентом, забраковано («акцент невозможно слушать»).

## Проверенные голоса SpeechKit v1

Мужские: `filipp` (диктор по умолчанию), `zahar`, `ermil` (neutral/good), `madirus`.
Женские: `jane` (neutral/good — низкий мягкий), `alena`, `omazh` (пожилая; `evil` работает).
`kirill` НЕ работает в v1 (HTTP 400). Докам верить нельзя — новый голос тестировать.

Базовый состав книги (из «Тонкой структуры»): ДИКТОР filipp 1.15 · МИТЧ zahar 1.0 · АННА jane 1.05 · ЧЭН ermil 1.05 · МЁРФИ zahar 1.1 · МУОКА ermil 1.1 · АРИКА jane 1.1 · ДЖЕЙСОН zahar 1.05 · МОКСОН madirus 1.15. Один человек = один голос во всей книге, личности склеиваются (МЁРФИ==МАЙК и т.п.).

## Формат ролевого сценария (script.md / roles-chNN.md)

```
@ДИКТОР: filipp neutral 1.15
@ГОЛОС: zahar neutral 1.1        # голос по умолчанию для неопознанных ролей
@gap: 0.5                        # пауза между репликами, сек

ДИКТОР: Название. Глава N.
ГЕРОЙ: Реплика.
@pause: 2                        # '***' в тексте = пауза, НИКОГДА не читается вслух
```

- Одна строка = одна реплика, `РОЛЬ: текст`.
- Ремарки («сказала она, смеясь») выносятся диктору; герой читает только свои слова.
- **Никогда не резать диалоги по тире автоматически** — русская проза полна тире, не являющихся диалогом (уже стреляло: голоса перепутались). Только ручная разметка ролей.
- **Никогда не резать авторское предисловие** (глоссарий тоже читается).
- Скорость диктора для книг: **1.15** (1.25 забракована — «быстровато»).

## Конвейер

1. Источник: FB2 → markdown (`src/fb2_to_md.py`) или скрейп рассказа (`src/fetch_story.py` — Literotica: `<article itemprop="articleBody">`, samlib: cp1251).
2. Перевод на русский, если нужно. Чистые .en.md и .ru.md сохраняются.
3. Ручная разметка ролей → script.md. **Показать пользователю ДО синтеза** — стоящее правило.
4. Синтез `src/voice_script.py script.md out.mp3`: резюмируемый (кэш сегментов в `.work-<name>/`), авто-замена неподдержанного голоса по HTTP 400, ретраи.
5. Склейка ffmpeg concat, паузы из @gap/@pause, `-c:a libmp3lame -q:a 2`.
6. Книги — один MP3 на главу, выход `fine-structure-*-chNN.mp3` (нуль-паддинг!).

## Длинные джобы в этой песочнице (важно)

- Прокси-туннель живёт, пока жив tool-call. `nohup` НЕ работает — процесс умирает вместе с вызовом.
- Рабочий паттерн: **managed background bash + network_mode:proxied + timeout_seconds:600**, без credential_ids (скрипт сам достаёт ключ; у credential пустой allowedTools — инжект откажут).
- Резюмируемый батч-скрипт (`src/run_roles.sh`) перезапускать на каждом wake, ~3 главы за 600-секундное окно, пока `ALL DONE`.
- Перед перезапуском проверять живые процессы: `pgrep -af "pytho[n]3 .*voice_script"` (класс `[n]` — чтобы pgrep не матчил сам себя). Два инстанса на одной главе дерутся за `.work`-каталог → rc=1.
- Ошибка «.work dir missing / sil.mp3: No such file» = глава УЖЕ готова (скрипт удаляет кэш при успехе). Проверить ffprobe, не перегонять.
