# narrator

Что тут происходит: я озвучиваю книжку Тонкая Структура ( Fine Structure ) с помощью LLM
это оказалось не просто, основная проблема с ударениями, я использую ruaccent, aot, pyllemm и много ручнвх правок с аудитом AI

## Стек

- **TTS: Yandex SpeechKit v1 REST** — единственный приемлемый русский голос.
  - Endpoint: `POST https://tts.api.cloud.yandex.net/speech/v1/tts:synthesize`
  - Auth: `Authorization: Api-Key $KEY`, ключ в vault (`assistant credentials reveal --service yandex --field api_key`, скрипт достаёт сам)
  - Поля формы: `text`, `lang=ru-RU`, `voice`, `emotion`, `speed`, `format=mp3`
  - Лимит текста: ~5000 символов на запрос → реплики склеиваются в чанки <4000
  - Сеть только через `network_mode: proxied`
- **Fallback: edge-tts** (ru-RU-DmitryNeural / SvetlanaNeural) — акцент норм, но ломает вопросительную интонацию.
- **ЗАПРЕЩЕНО: Deepgram Aura-2** — русский с неисправимым акцентом, забраковано («акцент невозможно слушать»).

## Проверенные голоса SpeechKit v1

Мужские: `filipp` (диктор по умолчанию), `zahar`, `ermil` (neutral/good), `madirus`.
Женские: `jane` (neutral/good — низкий мягкий), `alena`, `omazh` (пожилая; `evil` работает).
`kirill` НЕ работает в v1 (HTTP 400). Докам верить нельзя — новый голос тестировать.

Базовый состав книги (из «Тонкой структуры»): ДИКТОР filipp 1.15 · МИТЧ zahar 1.0 · АННА jane 1.05 · ЧЭН ermil 1.05 · МЁРФИ zahar 1.1 · МУОКА ermil 1.1 · АРИКА jane 1.1 · ДЖЕЙСОН zahar 1.05 · МОКСОН madirus 1.15. Один человек = один голос во всей книге, личности склеиваются (МЁРФИ==МАЙК и т.п.).

## Формат ролевого сценария (script.md / roles-chNN.md)

```
@ДИКТОР: filipp neutral 1.15
@ГОЛОС: zahar neutral 1.1        # голос по умолчанию для неопознанных ролей
@gap: 0.5                        # пауза между репликами, сек

ДИКТОР: Название. Глава N.
ГЕРОЙ: Реплика.
@pause: 2                        # '***' в тексте = пауза, НИКОГДА не читается вслух
```

- Одна строка = одна реплика, `РОЛЬ: текст`.
- Ремарки («сказала она, смеясь») выносятся диктору; герой читает только свои слова.
- **Никогда не резать диалоги по тире автоматически** — русская проза полна тире, не являющихся диалогом (уже стреляло: голоса перепутались). Только ручная разметка ролей.
- **Никогда не резать авторское предисловие** (глоссарий тоже читается).
- Скорость диктора для книг: **1.15** (1.25 забракована — «быстровато»).

## Конвейер

1. Источник: FB2 → markdown (`src/fb2_to_md.py`) или скрейп рассказа (`src/fetch_story.py` — Literotica: `<article itemprop="articleBody">`, samlib: cp1251).
2. Перевод на русский, если нужно. Чистые .en.md и .ru.md сохраняются.
3. Ручная разметка ролей → script.md. **Показать пользователю ДО синтеза** — стоящее правило.
4. Синтез `src/voice_script.py script.md out.mp3`: резюмируемый (кэш сегментов в `.work-<name>/`), авто-замена неподдержанного голоса по HTTP 400, ретраи.
5. Склейка ffmpeg concat, паузы из @gap/@pause, `-c:a libmp3lame -q:a 2`.
6. Книги — один MP3 на главу, выход `fine-structure-*-chNN.mp3` (нуль-паддинг!).

## Видео-конвейер (v8+, сегментный)

Глава собирается из **сегментов по одному на сцену** (`src/seg_video.py`, крутится на YC VM, НЕ на ai):

1. **Реанкоринг таймингов.** Сцены в `scenes-timing.md` привязаны к таймкодам v6. Скрипт мапит старт каждой сцены на индекс ближайшего кью в SRT v6 и берёт таймкод кью с тем же индексом из SRT текущей версии. Поэтому дрейф версий (у v8 до +16 с на главу) не ломает монтаж — перепривязка по индексу, не по абсолютному времени. Контроль: число кью v6 == v8, иначе assert.
2. **Сегмент.** Один ffmpeg на сцену: статичная картинка (`img-linked/`, со вжжёной ссылкой на GitHub) + срез аудио `-ss/-t` из MP3 главы. Кодируется независимо → сегменты кэшируются.
3. **Кэш.** `seg/manifest.json` хранит {сцена: картинка, start, end, версия}. Сегмент с совпадающей записью не перерендеривается — **новая версия книги пересобирает только сцены с изменившимся звуком**, остальные идут из кэша.
4. **Сборка.** `ffmpeg -f concat -c copy` склеивает сегменты главы без перекодирования; тут же приклеивается **субтитровая дорожка mov_text** (rus, по-предложенно, пропорциональные тайминги внутри кью).
5. **В кадр вжжёна только ссылка** `https://github.com/anatolix/narrator/` (drawtext через `textfile=` — двоеточие в URL ломает `text=`). Вшитых титров НЕТ — субтитры отключаемые (решение Анатолия, Sep 26).
6. **Сжатие статики:** `SEG_FPS=2 SEG_CRF=26 SEG_GOP=60` (env) — визуально неотличимо от 24fps/CRF20, размер −84% (2.0 МБ vs 12.9 МБ на 49-сек сцене; ch01: 17.7 МБ за 8.7 мин).
7. **Доставка:** главы «NN - Название.mp4» → S3 `video8/`, затем релеем на Яндекс Диск `/Juno/video8` (presigned URL → Yandex import). Аудио — `audio8/` → `/Juno/audio8`.

## Длинные джобы в этой песочнице (важно)

- Прокси-туннель живёт, пока жив tool-call. `nohup` НЕ работает — процесс умирает вместе с вызовом.
- Рабочий паттерн: **managed background bash + network_mode:proxied + timeout_seconds:600**, без credential_ids (скрипт сам достаёт ключ; у credential пустой allowedTools — инжект откажут).
- Резюмируемый батч-скрипт (`src/run_roles.sh`) перезапускать на каждом wake, ~3 главы за 600-секундное окно, пока `ALL DONE`.
- Перед перезапуском проверять живые процессы: `pgrep -af "pytho[n]3 .*voice_script"` (класс `[n]` — чтобы pgrep не матчил сам себя). Два инстанса на одной главе дерутся за `.work`-каталог → rc=1.
- Ошибка «.work dir missing / sil.mp3: No such file» = глава УЖЕ готова (скрипт удаляет кэш при успехе). Проверить ffprobe, не перегонять.

## Пунктуация: многоточия и тире — НЕ ТЕРЯТЬ при конверсии

При конверсии текста в ролевой сценарий **многоточия «…» и тире «—» внутри фраз должны сохраняться**. Это не украшение, а смысл и ритм фразы:

- Многоточие — оборванная мысль, заикание, тянущаяся пауза. SpeechKit даёт на «…» паузу ~0.47с (против 0.30с без знака) и другую интонацию. Съеденное многоточие склеивает два предложения в одно и ломает смысл (реальный случай: «не можем делать поспешных… Мне кажется» превратилось в «не можем делать поспешных, мне кажется» — фраза потеряла обрыв).
- Тире внутри фразы («Задача проста — объяснить…», парные тире «— то есть так, как мы и сделали —») — пауза ~0.34с и структура предложения. Без тире TTS читает сплошняком.
- Диалоговые тире в начале абзаца — другое дело: они законно превращаются в префиксы ролей (`РОЛЬ:`) и не теряются, а ремарки «— сказал он» уходят диктору.

### Восстановление уже потерянного (fine-structure, сен 2026)

Если конвертер знаки уже съел, они восстанавливаются из исходника выравниванием по словам:
1. Токенизируем исходник (`art/fine-structure/fine-structure.ru.txt`) и скрипт (без префиксов ролей и `+`), выравниваем `difflib.SequenceMatcher` — выравнивание устойчиво к правкам ударений, ё-фикации и числительных.
2. Для каждого «…» / «—» в исходнике проверяем, есть ли знак в скрипте рядом с отображённой позицией.
3. Классификация тире: легитимные (начало строки диалога, после `.?!…»"`, ремарка после запятой) пропускаем; остальное — потери внутри фраз.
4. Вставка — между словами (маркеры `+` не трогаем). Результат для fine-structure: **383 многоточия + 310 тире** восстановлено, коммиты `5781d58`, `727a674`.
5. План всегда показывается человеку до записи — автоприменение без превью запрещено.

Скрипты: `scratch/ell/` (в workspace Juno, не в репо): `dash_check.py`, `dash_plan.py`, `dash_apply.py` + аналоги для многоточий.

**Главное правило: не терять знаки при конверсии с самого начала — восстановление это заплатка, а не процесс.**
