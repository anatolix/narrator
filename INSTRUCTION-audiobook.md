# Инструкция: FB2 → русская аудиокнига (Yandex SpeechKit)

Инструкция самодостаточна: исполнителю не нужен никакой контекст, кроме этого файла.
Репозиторий с инструментами: **github.com/anatolix/narrator** (SSH-ключ у исполнителя, скрипты — в `src/`).

Пайплайн: FB2 → markdown → (перевод) → ролевые сценарии по главам → разметка ударений → синтез MP3 через SpeechKit → архив на S3 → ссылка пользователю.

---

## Шаг 0. Что должно быть под рукой

- Python 3, ffmpeg, aws CLI, curl, git.
- **API-ключ Yandex SpeechKit** (начинается с `AQVN`, из vault: `assistant credentials reveal --service yandex --field api_key`).
- Для разметки ударений и S3: **авторизованный ключ сервисного аккаунта** (JSON с private_key, vault `yandex/authorized_key`) и **статический ключ** (20+40 символов, vault `yandex:s3_static_pair`). Три типа ключей YC не взаимозаменяемы: API-ключ — только app API (SpeechKit); статический — только S3; авторизованный (JWT→IAM) — compute/vpc.
- Рабочая папка: `/workspace/art/<slug>/` — исходники, сценарии, MP3.

## Шаг 1. Выкачать и распаковать FB2

Файл приходит аттачем в `conversations/…/attachments/<file>.fb2`. Конвертировать в текст:

```
python3 src/fb2_to_md.py <file.fb2> /workspace/art/<slug>/<slug>.txt
```

Скрипт сам: определяет zip-обёртку (магия `PK`), кодировку XML из первой строки, тащит `<book-title>`/`<author>`/`<lang>`, из `<body>` делает абзацы (`<title>` → заголовок `## Глава N`), снимает HTML-мнемоники, выпиливает сноски `[N]`. Печатает счётчики абзацев/слов/символов.

## Шаг 2. Перевод (необязательный, условный)

Сверить `<lang>` из шага 1. **Книги часто уже на русском** — тогда перевод не нужен. Если не ru: перевести весь текст с исходника (не по памяти), сохранить `<slug>.en.md` и `<slug>.ru.md`.

## Шаг 3. Ролевые сценарии по главам (обязательный, полным чтением)

1. Разрезать текст на главы по заголовкам `## Глава N`.
2. **Каждую главу прочитать целиком** и разметить роли вручную — это главная работа. Автоматическая разбивка диалогов по тире ЗАПРЕЩЕНА: русская проза полна тире, не являющихся диалогом, эвристика перепутывает голоса (проверено на практике). Люди, говорящие в книге, получают по одному голосу на всю книгу; одно лицо под разными именами = одна роль.
3. Формат — по одному файлу `roles-chNN.md` на главу (нуль-паддинг):

```
# Название книги — глава N

@ДИКТОР: filipp neutral 1.15
@ГОЛОС: zahar neutral 1.1
@ГЕРОЙ1: jane neutral 1.05
@gap: 0.5

ДИКТОР: Автор. Название.          # только в первой главе
ДИКТОР: Глава N, заголовок.
ДИКТОР: <абзац повествования>
ГЕРОЙ1: Реплика.
ДИКТОР: Ремарка (сказала она, смеясь).
@pause: 2.5
```

Правила:
- Одна строка = одна реплика, формат `РОЛЬ: текст`.
- Ремарки («— сказал он») выносятся ДИКТОРУ; герой читает только свои слова. Прямая речь от первого лица остаётся диктору.
- **`***` и разделители сцен заменять строкой `@pause: 2.5`** — синтезатор читает звёздочки вслух («звёздочка звездочка звездочка»).
- **Авторское предисловие и глоссарий не резать никогда** — читаются диктором.
- Между строками-репликами пустая строка (читаемость для человека).
- ДИКТОР = `filipp neutral`, скорость **1.15** (1.25 забракована пользователем — «быстровато»).
- Проверенные голоса v1: мужские `filipp`, `zahar`, `ermil`, `madirus`; женские `jane` (низкий мягкий), `alena`, `omazh`. `kirill` НЕ работает в v1 (HTTP 400). Новый голос — только после теста.
- **Показать сценарий пользователю ДО синтеза** — стоящее правило. Запуск только после его «поехали».
- Проверка без API: `python3 src/voice_script.py roles-ch01.md /tmp/x.mp3 --dry` — печатает каст и счётчики реплик.

## Шаг 4. Разметка ударений (обязательный)

SpeechKit v1 понимает `+` перед ударной гласной прямо в поле `text` (з+амок ≠ зам+ок). Размечаются **все слова** скриптов движком **ruaccent** (модель turbo3.1). В своей песочнице ruaccent OOM-kill — он работает только на ВМ в Yandex Cloud (шаг 5).

Готовый скрипт на ВМ: `mark_all.py` — читает `/home/ubuntu/scripts/roles-ch*.md`, пишет `/home/ubuntu/marked/roles_full-ch*.md`; сохраняет префиксы `РОЛЬ:`, `@`-директивы и пустые строки. Печатает итог по маркерам `+`.

Спек нет — реализовать по мере накопления правок от пользователя.

## Шаг 5. Поднять ВМ на Яндексе для разметки

Авторизованный ключ → PS256-JWT → IAM token → compute/vpc API. Готовые скрипты: `yc_iam.py` (выдаёт IAM token) и `yc_vm.sh` (создаёт сеть/подсеть/ВМ `juno-ruaccent`, 2 vCPU / 8 GB / 20 GB, ru-central1-a, ssh-ключ из метаданных).

Транспорт файлов на ВМ — **только через Object Storage как посредника** (прямой scp через прокси рвётся на больших файлах, одна порча md5-незаметная уже ловилась):

```
# из песочницы
tar czf scripts.tar.gz roles-ch*.md
aws s3 cp scripts.tar.gz s3://juno-ruaccent-2027131566/mark/ --endpoint-url https://storage.yandexcloud.net
aws s3 presign s3://juno-ruaccent-2027131566/mark/scripts.tar.gz --expires-in 7200 --endpoint-url https://storage.yandexcloud.net
# на ВМ (сеть у ВМ к YC-internal открыта, наружу почти всё закрыто — модели таскать тем же путём)
curl -L '<signed-url>' -o scripts.tar.gz && tar xzf scripts.tar.gz
```

На ВМ ruaccent требует три части (~700 МБ, тащить через тот же S3): дерево accentuator в workdir, блок koziev в site-packages пакета, и строго `transformers==4.46.3 + tokenizers<0.21` (5.x ломает токенизатор). `RUAccent()` конструктору аргументов НЕТ — workdir только в `load(...)`.

После разметки забрать `marked/roles_full-ch*.md` обратно (тем же S3-кругом) и **остановить ВМ** (`POST /instances/{id}:stop`) — диск сохраняется, биллинг падает до диска. ВНИМАНИЕ: публичный IP динамический, после старта смотреть заново.

## Шаг 6. Синтез через SpeechKit API

Endpoint `POST https://tts.api.cloud.yandex.net/speech/v1/tts:synthesize`, заголовок `Authorization: Api-Key <AQVN...>`, поля формы `text`, `lang=ru-RU`, `voice`, `emotion`, `speed`, `format=mp3`. Лимит ~5000 символов на запрос — `voice_script.py` сам склеивает соседние реплики одной роли в чанки <4000.

Батч по главам — `src/run_roles.sh`-обёртка: цикл по главам, MP3 главы уже есть → skip; иначе `python3 src/voice_script.py roles_full-chNN.md <slug>-roles_full-chNN.mp3`; любой rc≠0 → exit. Один MP3 на главу, нуль-паддинг.

Дисциплина длинных прогонов:
- **Один процесс в один момент.** Перед запуском `pgrep -af "pytho[n]3 .*voice_script"` — два инстанса на одной главе дерутся за `.work-chNN/` и убивают друг друга.
- Баш-вызов живёт 600 с максимум → запуск как managed background, перезапуск на каждый wake, пока в логе не `ALL DONE`. Скорость ~3 главы за окно.
- Прерывание внутри главы не страшно: сегменты кэшируются в `.work-<name>/`, готовые seg-N.mp3 пропускаются; точная граница резюма — наличие итогового MP3 главы (`[ -s "$out" ]`).
- `.work-*` каталоги не трогать руками, пока MP3 главы не собран — это единственная копия уже синтезированных сегментов. При успехе скрипт удаляет кэш сам.
- Ошибка «.work dir missing / sil.mp3: No such file» = глава УЖЕ готова. Проверить ffprobe, не перегонять.

Итог проверять: все `…-chNN.mp3` на месте, ffprobe по каждому, хронометраж из лога (`grep 'DONE' … | awk '{s+=$1}'` — `bc` в песочнице нет).

## Шаг 7. S3 и выкладка файлов

```
cd /workspace/art
tar czf <slug>-roles_full.tar.gz <slug>-roles_full-ch*.mp3
aws s3 cp <slug>-roles_full.tar.gz s3://juno-ruaccent-2027131566/ --endpoint-url https://storage.yandexcloud.net
# проверка — размер объекта должен совпасть байт-в-байт (прогресс CLI врёт, объект ложится)
aws s3 ls s3://juno-ruaccent-2027131566/<slug>-roles_full.tar.gz --endpoint-url https://storage.yandexcloud.net
aws s3 presign s3://juno-ruaccent-2027131566/<slug>-roles_full.tar.gz --expires-in 604800 --endpoint-url https://storage.yandexcloud.net
```

Подписанную ссылку (7 дней) отдать пользователю вместе со списком глав и суммарным хронометражем. Большие файлы пользователь качает ТОЛЬКО по S3-ссылке — мессенджер/клиент на сотнях мегабайт захлёбывается. Мелкие файлы (сценарии, сэмплы) — обычной `vellum://`-ссылкой.

## Шаг 8. Уборка

По слову пользователя: удалить локальные MP3 из `/workspace/art`, снести ВМ (или оставить STOPPED), удалить бакет, ротировать утёкшие ключи. Самому — ничего не удалять.
